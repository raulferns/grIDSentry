Storage Economics & Predicate Pushdown: Parquet vs CSV

Benchmarked across 1,147.37 MB of real-world PCAP flow logs

Storage Efficiency
LEGACY FORMAT

Raw Real-World CSV Logs

1,147.37 MB
Uncompressed Text Footprint
  • Row-oriented plain text requiring full file scans for every query
  • Zero predicate pushdown or column pruning capabilities
  • Overhead from repeated string-to-numeric casting on every worker
  • Inefficient distributed partition I/O on large clusters
OPTIMIZED LAKEHOUSE

Columnar Apache Parquet

378.52 MB
67.01% Footprint Reduction
  • Snappy-compressed columnar encoding achieving 67% space reduction
  • Column pruning reads only the 43 relevant feature dimensions
  • Predicate pushdown filters attack classes before deserialization
  • Embedded min/max statistics avoid full partition reads
